1. 项目共识：先对齐什么

一句话定位

以动物 Agent 为核心，覆盖游前个性化规划、游中空间导览互动、游后 AIGC 回忆生成的主题乐园智慧伴游方案。

本次交付主线

参赛方案可信、原型闭环可演示、宣传片能讲清“游前—游中—游后”的用户价值。

不可忽略的边界

名称和素材不代表官方合作；定位、照片、未成年人数据均需遵循授权、最小化采集、可撤回与删除原则。

2. 建议的分工与唯一负责人

每项工作只能有一位“直接负责人（DRI）”，其他人可以协作或评审。以下按四人小队设计；人数更少时合并角色即可。

4. 第一次团队会：30 分钟定四件事

  1. 锁定交付清单：比赛需要的文档、PPT、演示链接/录屏、宣传片和提交截止时间。
  2. 确定原型边界：把外部 Nuxt 原型迁入仓库、用子模块关联，或明确本仓库只维护材料与宣传片。
  3. 认领任务：为每项任务写清 DRI、截止日、验收样例和依赖项；不要只写“做地图”或“优化 AI”。
  4. 确定节奏：每天 10 分钟站会；每两天一次可演示版本；截止前 48 小时停止新增功能，只修复、录制、排版。

5. 推荐的 Git 协作流程

将此目录初始化后的内容推到一个私有 GitHub 仓库，邀请队友为 Collaborator。所有人各自克隆仓库，避免通过微信反复传压缩包。

# 每位队友首次操作
git clone <仓库地址>
cd ai大赛

# 开始一项小任务
git switch main
git pull --ff-only
git switch -c codex/feature-brief-name

# 完成后：先检查，再提交
git status
git add <本次确实要提交的文件>
git commit -m "feat(video): add post-trip ticket scene"
git push -u origin codex/feature-brief-name
  • 不要直接在 main 修改；通过 Pull Request 合并，至少让一位队友看过。
  • 一个分支只做一件可描述的事：feat/、fix/、docs/、chore/。
  • 不要提交 .env、账号密码、API Key、个人聊天记录、node_modules、大型可再生渲染缓存。提交前运行 git status。
  • 视频和图片源文件可能很大：保留交付必需的最终素材；源工程/大文件需要时使用 Git LFS 或单独云盘，并在 README 写明获取方式。

7. 质量门槛

一致性可演示可追溯隐私安全

  • 方案、原型、视频使用一致的命名、三阶段叙事、六位伙伴设定和数据口径。
  • 宣传片工程修改后，在 qiyu-remotion-video 执行 pnpm install 与 pnpm render 验证；不要只交付未播放过的代码。
  • 涉及排队、客流、定位或动物信息时，在演示中标明“模拟数据”或来源；路线距离、顺序等关键事实由确定性逻辑计算。
  • 演示账户、录屏和截图不得暴露私人信息、真实密钥或未经授权的用户照片。

8. 接下来最值得优先完成的任务

  1. 队长建立私有远程仓库、邀请队友，并在任务工具建立交付看板。
  2. 对 scripts/ 与 tmp/ 做一次分类：可复现脚本和必要素材提交；纯临时输出加入忽略规则。
  3. 明确并迁移（或关联）Nuxt 原型代码；这是当前材料与仓库之间最重要的可追溯性缺口。
  4. 先跑通一版“游前选伙伴 → 游中抵达触发 → 游后票根/回忆”的 3 分钟答辩演示，再增添细节。
